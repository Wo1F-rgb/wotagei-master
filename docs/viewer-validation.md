# 全画面・骨格表示・手持ち追従の検証

2026-09-12。Windows上のChromeを使用。iPhone実機の画面・音声遅延・処理性能は未測定。

## 検証素材と公開範囲

- 指定の [X投稿](https://x.com/emakari_love/status/2090797885625700592) の公開動画（1280×720、約30秒）。既存のX取り込み経路でMP4を取得した。
- ユーザー提供の動画1本。動画・検出座標・比較画像はリポジトリ外だけで保管し、公開成果物には含めない。
- CIは公開用の合成動画を使用。表示テストは実際の骨格モデルを読み込む。追従の画面連携テスト（`built-motion.mjs`）だけは既知のカメラ揺れを持つ骨格応答に差し替え、検出精度の検証とは区別する。実動画での検出・追従は別のローカル試験で確認。

## 全画面と再生

`tests/built-viewer.mjs` はビルド済みアプリを使う。390×844と844×390で、比較の上下／左右配置、重ね表示の全面利用、見出し・トラック・設定レールの非表示、ページのはみ出しがないことを確認する。

実Fullscreen APIと、APIが提供されない条件の両方を通す。動画要素の同一性、表示切替前後に追加シークがないこと、再生継続、再生中・停止中のタップによるコントロール表示／非表示、Enter・Spaceでの同じ切替、約3秒の自動非表示、スライダー後の再生復帰を検証する。ドラッグ中に終了した後も古い操作状態が残らないことを含む。

`tests/built-camera.mjs` は合成カメラストリームと実MediaRecorderを使い、録画中の全画面・回転で同じカメラトラックを保持して録画を続けることを確認する。実レンズ・iPhoneでの検証ではない。

## 見やすさ

実MediaPipeモデルで停止フレームと再生中の人物切り抜きを確認した。単体の切り抜き試験では、モデル準備約0.3秒、停止フレームの出力約0.4秒。3.5秒の再生試験は32/33サンプルでキャンバスが更新し、元動画は約3.4秒進行した。この処理時間はPCの試験条件に限る。

夜景・黒い服・速い動きでは、人物領域が欠ける場面がある。人物切り抜きを必須にせず、「通常」「骨格で比較」「人物だけ」「色分け」を選べるようにした。ガンマとコントラストは個別に調整できる。切り抜き・骨格・動画を同じ追従レイヤーへ配置し、補正座標が分離しないようにした。

骨格は表示をONにした動画だけ推論する。1ワーカー・1画像ずつ処理し、見えない関節や古くなった検出結果を描かない。実動画で再生中の線表示、OFFでの消去、表示設定の保存を確認した。2Dの推定線であり、フォームの正しさを保証するものではない。

## 手持ち追従

同じX動画と提供動画を読み、各動画の対象人物を選んで184組の対応フレームを解析した。旧実装の画面表示では有効場面11%。姿勢の方向・胴体比率の判定が不一致だと、位置情報まで破棄していた。

肩・腰の位置と倍率の採用条件を分離し、修正後のアプリで再解析すると有効場面87%になった。2、5、10、15、20、25秒で、三脚OFF側のCSS位置が変化し、ON側のレイヤーが固定されることを確認した。倍率については信頼できる基準と継続した測定がない場合に固定する。

この割合は「補正を生成できる場面の割合」であり、87%の精度や完全な重なりを示さない。動画間の拍・基本位置は事前に合わせる必要があり、異なるフォームと撮影時の移動を完全に分離するものではない。候補人物が曖昧な場面は引き続き棄却する。

単体テストでは既知のカメラ移動・ズームを加えた骨格、違う姿勢、外れ値、検出の欠落、シーク・速度・画面回転・補正強度0を検証する。再生処理は既存の同期機構を使い、追従はCSS補間だけで行う。

## 比較表示で動かなかった原因と再検証

全画面の比較表示では、同じ高さの2枠それぞれに映像を中央寄せしていたため、枠内の黒帯が中央に集まっていた。2本を縦横比どおりの大きさでまとめて配置し、中央の隙間をなくした。単体テストは縦長・横長・異なる縦横比の組み合わせを確認し、実ブラウザでは映像枠の接点、画面内への収まり、動画要素を作り直さないことを確認した。

位置追従の適用条件が「重ねる」だけだったため、比較表示では解析結果があっても位置のCSSを消していた。比較・全画面比較でも補正を適用し、比較ではその映像枠の大きさと補正前の座標を使って計算する。重ねるときの手動補正は別に保持する。

三脚OFF後はBPMの準備を待って対象確認を開く。確認を閉じた場合には繰り返し開かず、映像上から再開できる。解析済みならON/OFF・表示切替・回転で解析し直さず、保持した骨格から表示座標を再計算する。BPM／拍変更時は古い補正を停止し、設定を保存すると再解析の対象確認を出す。トラックの微調整では自動で画面を開かない。

Xの夜景動画＋以前提供された屋外の動画で実モデルを再実行し、184組・骨格応答370件（選択用2枚を含む）を得た。補正が有効な場面は87%。通常再生中の比較20点、重ねる12点、全画面比較12点のすべてでOFF側のCSS値が変化し、ON側は無変形だった。約3.7〜18.9秒の試験中、追従・表示切替による追加シークは0回。iPhone相当の390×844では2枠の接点が一致し、実画像でも中央の隙間が消えたことを確認した。画面全体の外側には縦横比を保つための黒帯が残る。

`tests/built-motion.mjs` は、BPM未設定→設定後の確認、中止、再開、比較／重ねる／全画面／回転中の連続更新、再生中の追加シーク・推論がないこと、手動補正の保持、両方OFFと位置の主役切替、BPM・拍編集後の古い補正の停止を検証する。これは既知の骨格応答による画面連携の回帰試験であり、姿勢検出の正確さを示すものではない。

単発の「今の1コマで合わせる」も、設定を開く／BPM・拍を変えると進行中の結果を無効化する。モデル準備の完了を設定変更後まで遅延させる回帰試験を追加し、古い結果が手動の位置を上書きしないことを確認した。
