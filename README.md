# ヲタ芸マスター

動画やインカメを、お手本と8カウントに合わせて比較するWebアプリ。HTML・CSS・JavaScriptと骨格モデルをGitHub Pagesで配信します。ChatGPTへのログイン、自前のアプリサーバー、APIキーは不要です。

## 使い方

1. お手本の動画ファイル、またはYouTubeの共有リンクを選びます。
2. 自分の動画ファイルを選ぶか、インカメを起動します。
3. 各動画の「設定 → 拍・BPM → 拍タップ」で「再生して拍を記録」を押し、動画の1、2、3…に合わせて毎拍タップします。終わったら練習画面に戻り、「同期再生」を押します。
4. ローカル動画同士なら、両方を体が見える場面で止めて「重ねる → 位置 → 今の姿勢でざっくり合わせる」を押します。傾きや上下・左右の遠近は手動調整できます。
5. 次回は「最近使ったもの」から保存済みの動画・URLを読み直せます。

## 拍タップと白い拍線

タップ間隔だけでなく、タップした動画の再生時刻からBPMと拍の位置を同時に推定します。最初にタップした拍を「1」として数えますが、その最初の時刻にも固定せず、有効なタップ全体から等間隔の拍線を当てはめます。大きく外れたタップや二重タップの影響を抑え、抜けた拍を推定します。上段の点が実際のタップ、白線と下段の点が補正後の拍です。白い拍線・8カウント・2本の動画の同期に同じBPMと起点を使います。

64回の入力は不要です。2回から暫定推定を始め、有効な結果をこの画面に保持します。「拍音で確認」で聴いてから「保存して戻る」でこの端末に保存します。4〜16回程度が目安です。途中でタップをやめても、停止・画面切替・動画終了でも結果は残ります。再生位置変更や読み込み中断では記録を区切り、違う区間のタップを混ぜません。「再生してやり直す」で新しい記録を始められます。新しい推定が成立するまでは既存のBPM・起点を維持します。

少数のタップではテンポの倍・半分や押し間違いを区別できない場合があります。すべてのタップが一律に遅れる癖はタップだけでは判別できないため、必要なら「拍の位置」か下の2本のトラックで微調整してください。テンポが途中で変わる曲は練習区間ごとに設定してください。

## 今の姿勢で骨格合わせ

「重ねる → 位置 → 今の姿勢でざっくり合わせる」で実行します。自動補正は位置移動と縦横同じ倍率だけです。両方が立ち姿勢なら、頭から両足首の中点までの高さと足元で合わせます。

体の曲がり・片足の浮き・姿勢の違いがある場合は、見えている胴体の左右・太もも・すねの長さの比から概算します。極端な比を除いた中央値で倍率を決め、両腰の中点（腰が見えない場合は両肩の中点）で位置を合わせます。頭や足の一部が隠れていても、使える部位が残っていれば実行できます。概算したことは画面に表示します。

肩の傾き・足の開き幅から画面の回転や遠近は推定しません。手動で決めた回転・遠近は保持し、再生中は補正を固定します。自動倍率は0.5〜2倍、移動は±100%に抑え、大きな差は手動調整に残します。奥行き方向の短縮や体格差は分離できないため完全一致ではありません。肩・腰や十分な長さが検出できない場合だけ、場面変更や「位置・濃さ」での手動調整を案内します。

## 背景を基準に画角を補正

各動画の「設定 → 画角」で試せます。人体の姿勢・体格に合わせて画面を変形する代わりに、背景の固定した基準を使います。

1. 動画を止め、「水平線2点」または「壁の四隅」を選びます。番号をドラッグして基準点を合わせます。矢印キーでも微調整できます。
2. 水平線では背景の線の左端・右端を指定します。足先や奥へ続く床の線は使いません。これは選んだ線を水平にする操作であり、真のカメラ回転角の推定ではありません。
3. 四隅では人物に近い、人物と平行な壁・窓・鏡などの長方形を、左上→右上→右下→左下で指定します。実物の横÷縦を入力します（横100・縦200なら0.5）。実物が正方形のときだけ「正方形」を選びます。人体や床の四角には合わせません。
4. 「補正を試す」で元映像と比較し、必要なら強さを弱めます。「採用して保存」で練習画面にも反映されます。各動画で個別に設定でき、端末に保存します。
5. 採用・解除時は古い補正との二重適用を避けるため、重ねる位置・倍率・回転・手動遠近をリセットします。画角補正後に見比べたい姿勢で位置を合わせ直してください。

人物の奥行き、隠れた手足、広角レンズの曲がり、撮影中のカメラ移動は補正できません。動画ファイル向けで、YouTube・インカメは未対応。元のファイルやBPMは変えません。通常映像・切り抜き映像・骨格表示に同じ行列を適用します。[調査と合成実験の結果](docs/camera-correction-research.md)に方法の比較・数値・出典をまとめています。

## 背景を切り抜く

各動画の「設定 → 表示 → 背景」で、次の方式を選べます。比較・設定画面では緑背景または透明の市松模様で輪郭を確認でき、「重ねる」画面では背景を透明にしてお手本を透かします。自分側は「重ねる → 位置 → 背景」からも変更できます。

- **人物を自動で切り抜く**：普通の動画やインカメから、MediaPipe Selfie Segmenterで人物の領域を推定します。「輪郭の絞り込み」を上げると、確かな人物の領域だけを残します。遠くの全身、速い動き、髪や指、サイリウムは欠けたり背景が残ったりする場合があります。
- **撮影した緑背景を消す**：グリーンバックで撮影済みの映像の緑を透明にします。「緑を消す強さ」で調整します。緑の衣服やサイリウムも消えるため、撮影時の色に注意してください。

元の動画ファイルは変更せず、切り抜き表示に同じ反転・位置・倍率・遠近設定を適用します。音声とBPM同期は元の動画プレイヤーを使います。表示の画像処理はWorker内で行い、長辺640px・最大約30fps、処理待ちは1フレームまでに制限します。実際のフレームレートと表示遅延は端末に依存し、速さを保証しません。重い場合は背景をOFFにしてください。

モデルはこのサイトから取得し、動画の画像を外部に送りません。Worker / OffscreenCanvas / ImageBitmapに対応するブラウザが必要です。処理失敗時は元の映像を表示します。YouTube埋め込みの切り抜き、切り抜き済み動画の書き出しは未対応です。「録画を保存」は背景処理前のカメラ映像です。背景の方式・強さ・確認用の色は、この端末に動画ごとに保存します。

## 各利用者の保存

- 動画のコピーとURL履歴は、その端末・ブラウザのIndexedDBに保存します。Cookieに動画を入れる方式ではありません。BPM・開始位置・反転設定は端末のlocalStorageに保存します。
- 動画をGitHubや運営者のサーバーへアップロードしません。各利用者のブラウザ内の履歴は、別の利用者の端末には共有されません。同じ端末・ブラウザを共用する人には同じ履歴が見えます。
- 別端末への同期、ログインアカウントごとのクラウド保存はありません。元の公開サイトとGitHub Pagesは別の保存領域なので、移行時は動画を一度選び直してください。
- 動画は最大10本、合計1GB、1本500MBまで。容量が足りない場合は以前の動画を勝手に消さず、保存できなかったことを表示します。その動画は今回の再生には利用できます。
- URLは最近30件。「履歴に残す」のOFF、個別削除、全履歴の削除ができます。削除対象はアプリ内のコピーで、写真アプリ等の元動画は消しません。
- ブラウザのデータ削除、プライベートブラウズ、空き容量不足などで履歴が消える場合があります。原本は写真アプリ等にも残してください。「保存領域を保護」はブラウザへの保護リクエストであり、永久保存の保証ではありません。

## 外部サービスとの通信

YouTubeは公式の埋め込みプレイヤーを使います。リンクを読み込んだ際にYouTubeへ通信します。動画データの取得・ダウンロード・音声抽出は行いません。YouTubeは反転・重ね合わせ・骨格解析には対応しません。広告、通信、頭出しの精度による同期のずれが生じる場合があります。

曲名でのBPM検索はブラウザからDeezerの公開カタログへ直接問い合わせます。Apple Musicの曲リンクはiTunes lookupで曲名を取得してから検索します。検索した曲名や曲IDは各サービスへ送られます。音源・動画ファイルは送りません。BPMが未収録の場合は推測値で埋めません。サブスク音源の抽出や同期再生には対応しません。外部サービスが利用できない場合は、音源解析・手入力・TAP・rekordbox XMLを利用できます。

音声解析・動画の軽量化・骨格推定は端末内で行います。骨格モデルはこのサイトから初回読み込みます。補正は平面近似であり、3Dの体や隠れた手足を復元するものではありません。フォーム差は画角補正後、重ねる位置・倍率・手動遠近を適用する前の2D角度差で、残る撮影角度の影響を含みます。

## GitHub Pagesへの公開

このリポジトリの Settings → Pages → Build and deployment → Source を **GitHub Actions** に設定します。mainへのpushでテストと静的ビルドを実行し、`dist-pages`を公開します。プロジェクトURLのサブディレクトリでも動く相対パスを使用しています。

GitHubが静的ファイルの配信を担当するため、PCや自分のサーバーを常時起動する必要はありません。YouTube・曲検索・初回のアプリ読み込みにはネット接続が必要です。完全オフライン動作を保証するService Workerは未実装です。iPhoneではSafariの共有からホーム画面に追加できます。

## 開発と検証

Node.js 24:

```sh
npm ci
npm test
npm run check
npm run build
node tests/built-worker.mjs
node tests/built-background-worker.mjs
node tests/static-output.mjs
```

`npm run dev` は開発時だけ使います。公開先の利用者には不要です。

保存・再読込・削除・容量制限はfake-indexeddbで検証します。音声解析は合成音のテストです。背景処理は合成画素・マスクと、ビルド済みWorkerの緑除去経路をメモリ上の2D描画代替で検証します。AIモデルの実映像での切り抜き精度・ブラウザ内のWorker動作・Safari実機の保存維持、実際の楽曲の解析精度、YouTubeの再生・同期、カメラ、動画デコード、骨格推定・遠近表示は実機での追加確認が必要です。

第三者ライブラリ・モデルのライセンスは依存パッケージと`public/`内のLICENSE・NOTICE類を参照してください。

## 音の基準と拍音プレビュー

下部の「速度・音」で「お手本の音／自分の音」を選びます。選んだ曲のBPMを基準に、もう片方の速度を合わせます。例：お手本150 BPM・自分120 BPMなら、自分の音を選び練習速度1倍にすると、お手本0.8倍・自分1倍になります。YouTubeは対応する速度に制約があるため、表示された速度候補から選んでください。インカメは音声を取得しません。

各動画の「設定 → 拍・BPM／拍の位置」の「拍音で確認」は、最初の「1」の2拍前（動画の範囲内）からその動画だけを等速・音声付きで再生します。白線が設定した拍、赤線が再生位置です。白線のタイミングでクリックを鳴らし、8拍ごとの「1」は高い音にします。停止・移動・終了で予約した拍音を取り消します。確認中の結果は「保存して戻る」を押すまで永続保存しません。

開始時の補正判定を120msから25msに縮め、停止していた自分の動画の再開時も再生前後で位置を合わせます。滑らかさ優先では連続シークせず最大±2%の速度調整、OFFでは最大±4%と大きなずれの位置補正を使います。「時計の差」は再生速度を加味した秒数です。画面の描画・デコード・Bluetoothの遅延まで測定した値ではありません。

軽量化では音声をAACで保持し、変換時に先頭時刻を自動で詰めない設定にしました。音声が失われた場合や開始位置・長さがずれた場合は適用せず元動画を保ちます。元々無音の動画やカメラ録画に音声を追加するものではありません。

## 動画ファイル同士の再生開始

開始位置を揃えるため、両方の動画を一度無音で準備し、要求された開始位置へ戻して両方のシーク・デコードが完了するまで待ちます。その後に同時に再生を要求し、開始時のメディア時計の差が25ms以内、開始位置からの進行が80ms以内であることを確認して映像と選択した音声を出します。準備中はプレビューを覆い、「開始を中止」でキャンセルできます。

再生後のシークで開始のずれを追いかける方式は、動画ファイル同士では廃止しました。ずれた試行は無音のまま開始位置へ戻して最大3回まで試し、それでも大きくずれる場合は停止して軽量化を案内します。再生位置が相手の動画の範囲外の場合、インカメ、YouTube埋め込みはこの準備処理の対象外です。とくにYouTubeはデコード完了を直接確認できず、ファイル同士と同等の開始精度は保証できません。

検証は読み込み・シーク・再生開始の遅延を模擬したテストです。iPhone実機の画面・音声出力の遅延を計測した値ではありません。
