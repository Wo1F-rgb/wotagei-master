# ヲタ芸マスター

動画やインカメを、お手本と8カウントに合わせて比較するWebアプリ。HTML・CSS・JavaScriptと骨格モデルをGitHub Pagesで配信します。ChatGPTへのログイン、自前のアプリサーバー、APIキーは不要です。

## 使い方

1. お手本の動画ファイル、またはYouTubeの共有リンクを選びます。
2. 自分の動画ファイルを選ぶか、インカメを起動します。
3. 各動画の「設定」で最初の「1」の位置とBPMを設定し、「同期再生」を押します。
4. ローカル動画同士なら「重ねる → 位置」で骨格合わせと上下・左右の遠近補正を調整できます。
5. 次回は「最近使ったもの」から保存済みの動画・URLを読み直せます。

## 各利用者の保存

- 動画のコピーとURL履歴は、その端末・ブラウザのIndexedDBに保存します。Cookieに動画を入れる方式ではありません。BPM・開始位置・反転設定は端末のlocalStorageに保存します。
- 動画をGitHubや運営者のサーバーへアップロードしません。各利用者のブラウザ内の履歴は、別の利用者の端末には共有されません。同じ端末・ブラウザを共用する人には同じ履歴が見えます。
- 別端末への同期、ログインアカウントごとのクラウド保存はありません。元の公開サイトとGitHub Pagesは別の保存領域なので、移行時は動画を一度選び直してください。
- 動画は最大10本、合計1GB、1本500MBまで。容量が足りない場合は以前の動画を勝手に消さず、保存できなかったことを表示します。その動画は今回の再生には利用できます。
- URLは最近30件。「履歴に残す」のOFF、個別削除、全履歴の削除ができます。削除対象はアプリ内のコピーで、写真アプリ等の元動画は消しません。
- ブラウザのデータ削除、プライベートブラウズ、空き容量不足などで履歴が消える場合があります。原本は写真アプリ等にも残してください。「保存領域を保護」はブラウザへの保護リクエストであり、永久保存の保証ではありません。

## 外部サービスとの通信

YouTubeは公式の埋め込みプレイヤーを使います。リンクを読み込んだ際にYouTubeへ通信します。動画データの取得・ダウンロード・音声抽出は行いません。YouTubeは反転・重ね合わせ・骨格解析には対応しません。広告、通信、頭出しの精度による同期のずれが生じる場合があります。

曲名でのBPM検索はブラウザからDeezerの公開カタログへ直接問い合わせます。Apple Musicの曲リンクはiTunes lookupで曲名を取得してから検索します。検索した曲名や曲IDは各サービスへ送られます。音源・動画ファイルは送りません。BPMが未収録の場合は推測値で埋めません。サブスク音源の抽出や同期再生には対応しません。外部サービスが利用できない場合は、音源解析・手入力・TAP・rekordbox XMLを利用できます。

音声解析・動画の軽量化・骨格推定は端末内で行います。骨格モデルはこのサイトから初回読み込みます。補正は平面近似であり、3Dの体や隠れた手足を復元するものではありません。フォーム差は補正前の2D角度差で、撮影角度の影響を含みます。

## GitHub Pagesへの公開

このリポジトリの Settings → Pages → Build and deployment → Source を **GitHub Actions** に設定します。mainへのpushでテストと静的ビルドを実行し、`dist-pages`を公開します。プロジェクトURLのサブディレクトリでも動く相対パスを使用しています。

GitHubが静的ファイルの配信を担当するため、PCや自分のサーバーを常時起動する必要はありません。YouTube・曲検索・初回のアプリ読み込みにはネット接続が必要です。完全オフライン動作を保証するService Workerは未実装です。iPhoneではSafariの共有からホーム画面に追加できます。

## 開発と検証

Node.js 24:

```sh
npm ci
npm test
npm run check
npm run build
node tests/built-worker.mjs
node tests/static-output.mjs
```

`npm run dev` は開発時だけ使います。公開先の利用者には不要です。

保存・再読込・削除・容量制限はfake-indexeddbで検証します。音声解析は合成音のテストです。Safari実機の保存維持、実際の楽曲の解析精度、YouTubeの再生・同期、カメラ、動画デコード、骨格推定・遠近表示は実機での追加確認が必要です。
